# Domain Docs

This repository uses a single domain context.

## Before exploring or implementing

- Read `CONTEXT.md` when it exists.
- Read relevant decisions under `docs/adr/` when they exist.
- Use glossary terms consistently in specs, issues, code, and tests.
- Surface conflicts with an accepted ADR instead of silently overriding it.

## Layout

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── src/
```

Create or extend domain documentation through the domain-modeling workflow when terminology or durable architectural decisions are resolved.
